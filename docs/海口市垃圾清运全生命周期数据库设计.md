# 海口市垃圾清运全生命周期数据库设计（精简版）

> **主题**：跟踪垃圾全生命流程（**产出 → 暂存 → 消耗**）的精简数据库，覆盖全部处理路径
> **当前版本**：v2.7（变更记录见文末第七章）
> **编制日期**：2026-10-10
> **上游文档**：《海口市垃圾处理全流程汇报》（docs/海口市垃圾处理全流程汇报.md）

***

## 一、设计思路

一张**流转单**记录一次车运的物理转移（一段一行）。垃圾是散装流质，**可追溯单元是"车次"而非物理批次**——在中转站压缩、贮坑、仓库混合后批次即断链，段与段之间靠设施节点与重量勾稽衔接；**暂存台账**按"设施+类别"记库存流水（仅可批次化品类记批次）；**消耗记录**记录末端实收及产出。共 **6 张表**构成全生命闭环：

```
dict_waste_category ─┐
dim_facility ────────┼─ 基础表
dim_vehicle ─────────┘
          │
          ▼
txn_transfer（流转单，脊柱）
   ├─ 产出：第一段 from=产生点（挂车辆）
   ├─ 暂存：to=暂存点 → txn_storage 库存流水
   └─ 消耗：终段 to=末端 → txn_disposal 实收+产出
```

## 二、表清单（6 张）

| # | 表名                    | 职责                         | 对应生命阶段  |
| - | --------------------- | -------------------------- | ------- |
| 1 | dict\_waste\_category | 垃圾类别及默认处置路径                | 决定走哪条路径 |
| 2 | dim\_facility         | 全链节点（产生源/投放点/转运站/暂存点/末端设施） | 所有"地点"  |
| 3 | dim\_vehicle          | 车辆档案：常规编制 + 临时借调，专车专类      | 承运工具    |
| 4 | txn\_transfer         | 流转单：每段车运一行，段间靠设施衔接         | 产出 + 流转 |
| 5 | txn\_storage          | 设施级暂存库存流水                  | 暂存      |
| 6 | txn\_disposal         | 末端消耗及资源化产出                 | 消耗      |

## 三、表结构定义

### 1. dict\_waste\_category 垃圾类别字典

| 字段               | 类型             | 说明                                                                                                         |
| ---------------- | -------------- | ---------------------------------------------------------------------------------------------------------- |
| category\_code   | VARCHAR(20) PK | 类别码：OTHER 其他、KN\_HOME 家庭厨余、KN\_CANTEEN 餐厨、HAZARD 有害、RECY 可回收、BULK 大件、CONSTR 建筑、GARDEN 园林、FECAL 粪渣、WATER 水域 |
| category\_name   | VARCHAR(50)    | 中文名称，界面报表展示用                                                                                               |
| default\_route   | VARCHAR(30)    | 这类垃圾默认去哪：焚烧 / 厨余餐厨厂 / 危废暂存 / 市场化回收 / 大件拆解 / 建筑资源化 / 堆肥                                                     |
| is\_market\_line | BOOLEAN        | 是否市场化回收线（不经环卫，市场单不参与环卫考核）                                                                                  |

> 规则：编码一经使用不可改名、不可复用（历史单据都挂在旧编码上）；默认路径不强制，实际改道记在流转单 reclass\_from。

### 2. dim\_facility 设施表（全链节点，含产生源）

| 字段                             | 类型             | 说明                                                                                    |
| ------------------------------ | -------------- | ------------------------------------------------------------------------------------- |
| facility\_id                   | VARCHAR(20) PK | 设施编码，各类节点共用一套编码——流转单 from/to 统一外键的前提                                                  |
| facility\_name                 | VARCHAR(100)   | 设施名称，建议带属地前缀（如"秀英区白水塘转运站"）                                                            |
| facility\_type                 | VARCHAR(20)    | 节点角色：SOURCE 产生源 / DROP 投放点 / COLLECT 收集点 / TRANSFER 转运站 / STORAGE 暂存点 / TERMINAL 末端设施 |
| region\_code                   | VARCHAR(12)    | 所辖区划（区/街道/村），统计分组维度                                                                   |
| address / longitude / latitude | —              | 位置，坐标必填（清运地图与线路规划依赖）                                                                  |
| capacity\_ton\_day             | DECIMAL        | 设计能力（吨/日），设施负荷率的分母                                                                    |
| operator                       | VARCHAR(100)   | 运营方名称（文本）                                                                             |
| type\_attrs                    | JSON           | 类型专属属性：转运层级、末端装机参数、暂存限收品类、投放点桶数、产生源签约标记等                                              |
| status                         | VARCHAR(10)    | RUNNING 运行 / BUILDING 在建 / SHUTDOWN 关停（新流转单禁止指向）                                      |

> 产生源就是 type=SOURCE 的设施行——餐厅签约、小区、工地都在这张表。

### 3. dim\_vehicle 车辆表

| 字段                      | 类型             | 说明                                                                                                       |
| ----------------------- | -------------- | -------------------------------------------------------------------------------------------------------- |
| vehicle\_id             | VARCHAR(20) PK | 内部车辆号，车牌变更也不变（保证历史单据可追溯）                                                                                 |
| plate\_no               | VARCHAR(15) UK | 车牌号，地磅/道闸自动识别用                                                                                           |
| vehicle\_type           | VARCHAR(20)    | 车型：OTHER\_TRUCK 其他垃圾车 / KITCHEN\_TRUCK 厨余车 / HAZARD\_TRUCK 有害车 / BULK\_TRUCK 大件车 / TRANSFER\_TRUCK 大型转运车 |
| allowed\_category       | VARCHAR(20) FK | 允许运输的类别，专车专类——建单时校验，不满足即拒单（防混装混运）                                                                        |
| load\_ton               | DECIMAL(6,2)   | 核载（吨），运力利用率分母                                                                                            |
| owner\_org              | VARCHAR(100)   | 所属单位（文本）                                                                                                 |
| enrollment\_type        | VARCHAR(10)    | REGULAR 常规编制 / TEMP 临时借调（政府借调、跨区调度、社会租赁）                                                                 |
| lender\_org             | VARCHAR(100)   | 借调/支援单位，TEMP 必填                                                                                          |
| valid\_from / valid\_to | DATE           | 借调时间窗，TEMP 必填；到期自动失效不可派单                                                                                 |
| status                  | VARCHAR(10)    | ACTIVE 在役 / REPAIR 维修 / RELEASED 已退场 / RETIRED 报废                                                        |

> 初始化仅录常规编制（其他 389 / 厨余 95 / 有害 5，2025 年；农村约 2706 辆）。临时借调车辆不预置——事件发生时即借即登，用毕置 RELEASED 退场、不删档，历史流转单仍可追溯。

### 4. txn\_transfer 流转单（核心脊柱，一段一行）

| 字段                           | 类型               | 说明                                                          |
| ---------------------------- | ---------------- | ----------------------------------------------------------- |
| transfer\_no                 | VARCHAR(30) PK   | 流转单号 `HK-{日期}-{类别}-{流水}`，一次车运一张单                            |
| batch\_no                    | VARCHAR(30) NULL | 批次号，把未混合的续段串成旅程：直运、同箱续运、厂内残渣续段、有害垃圾必填；跨中转混装不填（靠设施节点+重量勾稽衔接） |
| leg\_seq                     | TINYINT          | 段序：1=产出段，同批次续段递增                                            |
| category\_code               | VARCHAR(20) FK   | 本单垃圾类别，与车辆 allowed\_category 联动校验                           |
| reclass\_from                | VARCHAR(20)      | 分类不合格改道时的原类别（如厨余→其他垃圾）                                      |
| weight\_kg                   | DECIMAL(10,2)    | 本段装运重量，全链勾稽与单车次装载率的分子                                       |
| from\_facility\_id           | VARCHAR(20) FK   | 起点设施（产出段=投放点/产生源，转运段=中转站）                                   |
| to\_facility\_id             | VARCHAR(20) FK   | 终点设施（中转站/暂存点/末端），禁止指向已关停设施                                  |
| vehicle\_id                  | VARCHAR(20) FK   | 承运车辆，含临时借调车辆（借调时间窗须覆盖装运时间）                                  |
| carrier\_org                 | VARCHAR(100)     | 承运单位（文本冗余，报表直出）                                             |
| status                       | VARCHAR(12)      | LOADED 在途 / ARRIVED 已到达 / CONFIRMED 已签收（终段签收+消耗记录=闭环）       |
| loaded\_time / arrived\_time | DATETIME         | 装/到时间，中转站"不过夜"稽核依据                                          |
| emergency\_flag              | BOOLEAN          | 应急标记（台风等），应急清运量单独统计                                         |

### 5. txn\_storage 暂存台账（设施级库存流水）

| 字段                    | 类型                  | 说明                                           |
| --------------------- | ------------------- | -------------------------------------------- |
| storage\_id           | VARCHAR(28) PK      | 流水号，一次入库、一次出库各记一行                            |
| facility\_id          | VARCHAR(20) FK      | 暂存设施：有害暂存点 / 焚烧厂贮坑 / 可回收仓 / 建筑调配场 / 中转站      |
| category\_code        | VARCHAR(20) FK      | 类别，可限收（如有害点只收 HAZARD，限收写在设施 type\_attrs）     |
| io\_type              | VARCHAR(10)         | IN 入库 / OUT 出库                               |
| quantity              | DECIMAL(12,2)       | 本行数量                                         |
| unit                  | VARCHAR(10)         | 单位，默认吨（建筑垃圾用 m³）                             |
| io\_time              | DATETIME            | 出入库时间，滞留天数与超期预警以此为时钟                         |
| batch\_no             | VARCHAR(30) NULL    | 批次号，仅有害垃圾等可批次化品类必填；散装品类混堆不填                  |
| reason                | VARCHAR(12)         | NORMAL 常规 / PROCESS 工艺性（贮坑发酵） / EMERGENCY 应急 |
| related\_transfer\_no | VARCHAR(30) FK NULL | 关联流转单，把"停下来"与"动起来"缝在一起                       |

> 口径：库存量 = ΣIN − ΣOUT（按设施+类别聚合，不存库存字段）；有害按批次 >365 天预警；贮坑滞留 >7 天预警；中转站当日进出平衡即"不过夜"。

### 6. txn\_disposal 消耗记录

| 字段               | 类型               | 说明                                                                                                        |
| ---------------- | ---------------- | --------------------------------------------------------------------------------------------------------- |
| disposal\_id     | VARCHAR(28) PK   | 消耗记录号——一条记录 = 一批垃圾在系统里消失                                                                                  |
| facility\_id     | VARCHAR(20) FK   | 末端设施，须 type=TERMINAL（焚烧/餐厨/厨余/大件/建筑/危废）                                                                   |
| transfer\_no     | VARCHAR(30) FK   | 终段流转单，一一对应                                                                                                |
| batch\_no        | VARCHAR(30) NULL | 批次，仅可批次化品类填写（有害垃圾全程批次还原）                                                                                  |
| category\_code   | VARCHAR(20) FK   | 消耗类别，支撑分类处置量统计                                                                                            |
| weight\_kg       | DECIMAL(10,2)    | 末端实收重量，与流转单重量的差值超容差即告警                                                                                    |
| disposal\_method | VARCHAR(20)      | 消耗方式：INCINERATION 焚烧发电 / ANAEROBIC 厌氧产沼 / COMPOST 堆肥 / DISASSEMBLE 拆解 / RECYCLE 再生利用 / HAZARD\_TREAT 危废处置 |
| outputs          | JSON             | 资源化产出："垃圾消失了，换来了什么"——电力（kWh）、炉渣砖、沼气、生物柴油、有机肥                                                              |
| consume\_time    | DATETIME         | 消耗完成时间，全生命周期的终点锚点                                                                                         |
| reject\_reason   | VARCHAR(100)     | 拒收原因，拒收则流转单状态回退                                                                                           |

## 四、全路径覆盖对照

| 处理路径                  | 6 张表的表达                                                                                                               |
| --------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **直运**（产生→焚烧厂，不经中转）   | transfer 1 行：from=投放点，to=焚烧厂；disposal 1 行                                                                             |
| **汇运**（产生→白水塘/江东→焚烧厂） | transfer 2 行（收集车 1 行 + 转运车 1 行；混装断链不填批次，两行经中转站节点与重量勾稽衔接）；过夜靠 arrived\_time 稽核                                         |
| **有害垃圾**              | transfer: 产生点→暂存点；storage: 暂存点出入库（**填 batch\_no**，>365 天预警）；transfer: 暂存点→危废单位；disposal: 危废处置                         |
| **焚烧厂贮坑工艺暂存**         | disposal 前 storage 1 行（facility=焚烧厂，reason=PROCESS）                                                                   |
| **餐厨/家庭厨余**           | transfer 直达厨余/餐厨厂；disposal method=ANAEROBIC，outputs=沼气/柴油/有机肥                                                         |
| **可回收物（市场化线）**        | transfer: 产生点→分拣仓（carrier=再生资源企业）；storage 短期暂存；disposal method=RECYCLE                                                |
| **大件垃圾**              | transfer→大件厂，disposal method=DISASSEMBLE；残渣续段填同 batch\_no：transfer 大件厂→焚烧厂                                            |
| **建筑/园林/粪渣**          | 类别字典 default\_route 区分；建筑经调配场（storage 调剂期）→资源化厂                                                                       |
| **分类不合格改道**           | transfer.reclass\_from=KN\_HOME，按 OTHER 走焚烧（拍照留底 URL 放 remark 类字段或扩展）                                                 |
| **应急（台风）**            | transfer.emergency\_flag=1；storage.reason=EMERGENCY 临时堆放；借调车辆即借即登 dim\_vehicle（TEMP + lender\_org + 时间窗），退场置 RELEASED |
| **无填埋兜底**             | 字典无填埋路径；颜春岭 facility status=SHUTDOWN                                                                                  |

**闭环判定**：流转链走到 txn\_disposal（终段被末端签收）= 完成"产生→消耗"全生命周期；只有 transfer 没有 disposal = 在途或在库。散装混合品类的追溯口径是**车次+重量勾稽**，不承诺物理批次全程还原；可批次化品类（有害等）用 batch\_no 全程还原。

**运力利用率（派生指标，不落列）**：荷载=dim\_vehicle.load\_ton，实载=txn\_transfer.weight\_kg（一段一行即一次车运），二者已有字段联算即可。

- 单车次装载率 = weight\_kg / load\_ton，>100% 触发超载告警

- 期间运力利用率 = Σ weight\_kg ÷ Σ(车次数 × load\_ton)，按区域/垃圾类别/日期分组；按 enrollment\_type 分组可单独统计借调车辆的应急运力贡献；基准值待运行数据积累后校准

- 实现方式：建视图 `v_vehicle_utilization` 或并入日统计扩展表，不存明细列

- 边界：流转单只记重载段（有货建单），本指标是**重载装载率**；含空驶返程的"里程利用率"需作业任务/轨迹数据，属扩展位

### 评审决策详情（由变更引申的设计说明）

**设施是否按类别分别建表（v2.3）——结论：不拆，维持单表**

决定性理由：垃圾全生命流程的本质是"同一批垃圾流经不同类型的节点"，流转单的 from/to 必须统一外键——拆表后需 5\~6 对起止字段或放弃外键完整性的多态关联，且大件厂残渣→焚烧厂、调配场→资源化厂这类最典型的"节点间转换"会变成跨表对接；覆盖对照表中的 11 条路径查询全部退化为类型判断+UNION。拆表唯一真实优势（各类属性干净）由 `type_attrs` JSON 承接；若将来某类属性膨胀（如末端设施的炉排炉数、装机容量、发电指标），升级为**主表+类型子表**（1:1 垂直扩展，共享 facility\_id 主键），from/to 外键依然统一，不推翻本设计。规模上全部设施约 8000 行，单表无压力。

**暂存台账批次字段评估（v2.1）——结论：降级为可空、设施级流水**

生活垃圾散装混合——中转站压缩装箱、贮坑发酵、仓库堆存后，入库物与出库物无法按批次对应，批次级暂存台账会逼出假数据。故台账记到**设施+类别**粒度；只有可批次化的品类才填 batch\_no（有害垃圾须包装容器化、标签化，法规要求批次台账）。散装品类的段间衔接靠设施节点+重量勾稽，不承诺物理批次全程还原。
