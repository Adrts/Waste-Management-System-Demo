> **主题**：明确垃圾全生命周期管理 DEMO 的项目目的、建设程度目标与验收指标体系
> **当前版本**：v1.0
> **编制日期**：2026-10-10
> **上游文档**：《海口市垃圾处理全流程汇报》（docs/海口市垃圾处理全流程汇报.md）、《海口市垃圾清运全生命周期数据库设计（精简版）》（docs/海口市垃圾清运全生命周期数据库设计.md，v2.7）

## 一、项目背景与定位

### 1.1 背景

海口市生活垃圾实行"四分类 + 分类投放—分类收集—分类运输—分类处置"全链条闭环管理，全市约 **3500 吨/日、130 万吨/年**。当前各环节数据分散在收运企业、转运站、末端设施等多方，存在两个痛点：

1. **数据断链**：缺少一条把"一车垃圾从产生到销毁"完整串起来的数据主线，混装混运、勾稽不平、超期滞留等问题难以追溯；
2. **决策靠经验**：运力储备（车辆、班次、人员）主要靠经验估计，春节等传统节日垃圾量脉冲上涨、台风等灾害导致清运量激增时容易被动。

### 1.2 项目定位

- **智慧城市系统的子系统**：本项目是智慧城市固废板块的核心模块，向上可对接城市运行管理平台，向外引入经济发展数据、自然灾害临近信息、农历/公历节日等外部数据。
- **DEMO 性质**：以海口市真实业务结构与流程为蓝本、**数据缩比模拟**的演示验证系统。目标是验证"**全生命周期数据链 + 统计预测决策**"这条技术路线的可行性与业务价值，不追求生产级规模与性能（边界见第七章）。

## 二、项目目的

**总目标（一句话）**：把垃圾"从产生到销毁"的全过程数字化、可视化，并用统计分析方法把数据变成预测与决策依据，帮助决策者科学规划运力储备。

分解为四个分目的：

| # | 分目的 | 说明 | 承载模块 |
|---|---|---|---|
| P1 | **全程可追溯** | 每一车垃圾从产生点 → 投放/收集 → 中转/暂存 → 末端处置 → 资源化产出，全程有单可查、有账可勾稽 | 后端数据库（6 表，流转单为脊柱） |
| P2 | **状态可感知** | 管理者通过展板实时看到全市垃圾产出、流转、处置、运力、预警状态 | 前端数据展板 |
| P3 | **数据可管理** | 业务人员在线完成建单、签收、出入库、改道、应急登记等日常操作，系统自动校验防错 | 前端数据管理页面 |
| P4 | **决策可量化** | 融合外部数据（经济、灾害、农历节日），运用回归分析、时间序列、马尔可夫链、主成分分析等方法预测垃圾量，输出运力储备建议 | 统计分析与预测模块 |

## 三、系统构成与建设范围

```
┌─────────────────────────────────────────────────────────┐
│                    外部数据（离线导入）                     │
│   经济发展数据 · 台风/灾害临近信息 · 农历-公历节日映射        │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌──────────────┐   ┌──────────────────┐   ┌──────────────┐
│  前端数据展板  │◄──│   统计分析模块     │◄──│  后端数据库    │
│ (可视化+预警) │   │ 回归/时序/马氏链/PCA│   │ (6 表+模拟数据)│
└──────────────┘   └────────┬─────────┘   └──────▲───────┘
                            ▼                    │ 增删改查/校验
                   ┌──────────────────┐          │
                   │  前端数据管理页面   │──────────┘
                   └──────────────────┘
```

| 构成 | 内容 |
|---|---|
| 后端数据库 | 按《数据库设计》v2.7 建 6 张表：`dict_waste_category`、`dim_facility`、`dim_vehicle`、`txn_transfer`、`txn_storage`、`txn_disposal`；含缩比模拟数据生成器 |
| 前端数据展板 | 全局 KPI、类别结构、时序趋势（叠加预测线与节日/台风标注）、设施地图与流向、预警中心、运力建议卡 |
| 前端数据管理页面 | 6 表增删改查、流转单建单校验（专车专类、关停设施、借调时间窗、批次规则）、状态流转与拒收回退、异常登记、追溯查询 |
| 统计分析模块 | 描述性统计、多元回归、时间序列预测、马尔可夫链、主成分分析（PCA）、运力储备测算；外部数据接入与特征构造 |

## 四、建设程度目标（做到什么程度算完成）

DEMO 完成度分三层，**验收以"目标层"为通过线**：

| 层级 | 内容 | 性质 |
|---|---|---|
| **基线层** | 6 表数据库建成并灌入覆盖全部路径的模拟数据；管理页可完成全流程操作；展板呈现描述性统计全部指标 | 缺任何一项视为未完成 |
| **目标层（通过线）** | 在基线上完成四类分析模型（回归、时间序列、马尔可夫链、PCA）并产出可用结果；基于预测输出未来 7/30 天运力储备建议；三个演示场景完整走通 | **验收通过必须全部达成** |
| **愿景层（加分）** | 多模型对比选优与误差报告；台风/节日情景模拟推演（假设分析 what-if）； PCA 因子用于聚类分区；运力建议给出置信区间与方案对比 | 不影响通过，影响评级 |

## 五、验收指标体系

### 编号规则

`D-`数据层 · `F-`管理页功能 · `V-`展板 · `A-`统计分析 · `P-`性能 · `S-`演示场景。每条指标给出**可验证的口径与验收标准**，验收时逐条对照打勾。

### 5.1 数据层指标（D）

| 编号 | 指标 | 口径 | 验收标准 | 验证方式 |
|---|---|---|---|---|
| D-1 | 表结构一致率 | 实际建表与《数据库设计》v2.7 的 6 张表字段比对 | 字段名/类型/约束一致率 **100%**（允许按 DBMS 微调类型写法） | 脚本比对建表 SQL |
| D-2 | 模拟数据时间跨度 | 流转单覆盖的连续日期范围 | **≥ 730 天**（覆盖两个春节周期、至少一个台风季） | SQL 查询 min/max 日期 |
| D-3 | 数据规模 | 流转单行数、日均车次 | 流转单 **≥ 10 万行**，日均 **≥ 300 车次** | 行数统计 |
| D-4 | 主数据覆盖度 | 设施数、车辆数、类别数 | 设施 **≥ 100**（含投放点/收集点/转运站/暂存点/末端），车辆 **≥ 120**（含 ≥ 3 辆临时借调样本），**10 个类别全覆盖** | 查询分组计数 |
| D-5 | 全路径样本覆盖 | 按《数据库设计》第四章 9 类处理路径 | 每条路径（直运/汇运/有害/贮坑/厨余/回收/大件/建筑/改道/应急）**均有可查样本** | 逐路径 SQL 抽查 |
| D-6 | 勾稽平衡率 | 终段消耗重量与流转单重量差在容差内的比例 | 容差内 **≥ 99%**，且故意注入的勾稽异常样本（≥ 5 条）**全部触发异常记录** | 脚本核算 |
| D-7 | 库存口径正确性 | txn_storage 按设施+类别 ΣIN − ΣOUT | 与展板显示库存一致，**误差为 0** | 抽 3 个设施×类别核算 |
| D-8 | 注入业务规律 | 模拟数据中预埋的统计规律 | 春节前 7 天厨余/其他垃圾量上浮约 **+30%**、台风临近 72h 清运量上浮约 **+50%**、周末小高峰 **+10%**（规律清单随数据交付） | 规律清单+时序图核对 |

### 5.2 管理页功能指标（F）

| 编号 | 指标 | 验收标准 | 验证方式 |
|---|---|---|---|
| F-1 | 6 表基础 CRUD | 每张表可增、删（软删/停用）、改、查；`dict_waste_category` 已使用编码**禁止改名/复用** | 现场操作 |
| F-2 | 专车专类校验 | 建单时类别与车辆 `allowed_category` 不符即**拒单并提示** | 现场构造拒单 |
| F-3 | 状态机流转 | 流转单 LOADED → ARRIVED → CONFIRMED 依次推进；终段签收联动生成消耗记录；拒收则状态**回退** | 现场走单 |
| F-4 | 批次规则校验 | 有害垃圾建单**必须填 batch_no**；跨中转混装续段**不允许填**批次 | 现场构造两种情况 |
| F-5 | 借调车辆管理 | 临时车辆"即借即登"（TEMP+lender_org+时间窗）；时间窗外的派单**被拒**；退场置 RELEASED 后历史单据仍可查 | 现场操作 |
| F-6 | 异常登记 | 分类不合格改道（reclass_from）、应急标记（emergency_flag）、暂存出入库（含 PROCESS/EMERGENCY 原因）均可登记 | 现场操作 |
| F-7 | 追溯查询 | 按流转单号/批次号/设施/类别/时间段任一条件查询；有害垃圾按 batch_no **还原全旅程**（产生→暂存→处置） | 现场查询 |
| F-8 | 操作防错 | 指向 SHUTDOWN 设施的新建流转单被拒；表单必填项与枚举校验生效 | 现场构造 |

### 5.3 数据展板指标（V）

| 编号 | 指标 | 验收标准 | 验证方式 |
|---|---|---|---|
| V-1 | 全局 KPI 卡 | 今日清运量/处置量、在途车次、无害化处置率、运力利用率、预警数，**口径与数据库派生视图一致** | 与 SQL 结果比对 |
| V-2 | 类别结构 | 四分类及全部 10 类别占比图，支持按区域/时间筛选 | 现场操作 |
| V-3 | 趋势图 | 日产生/清运/处置时间序列；**节假日、台风期在图上标注**；预测曲线与实际值叠加显示 | 现场查看 |
| V-4 | 设施视图 | 设施地图（含经纬度）+ 设施负荷率排行；流向桑基图（产生→中转→末端）可看 | 现场查看 |
| V-5 | 预警中心 | 超期滞留（有害 >365 天、贮坑 >7 天）、勾稽异常、超载、中转"过夜"告警**逐条列出并可下钻到原始单据** | 现场下钻 |
| V-6 | 运力建议卡 | 展示未来 7/30 天分品类垃圾量预测与**建议车辆数/班次**，注明模型与置信水平 | 现场查看 |

### 5.4 统计分析指标（A，核心）

> 验证逻辑：模拟数据按 D-8 预埋了已知规律，**模型"找回"这些规律即证明方法实现正确**。

| 编号 | 指标 | 口径 | 验收标准 | 验证方式 |
|---|---|---|---|---|
| A-1 | 描述性统计 | 按类别/区域/日的产生量、清运量、处置量、单车装载率（weight_kg/load_ton）、设施负荷率、运力利用率 | 指标齐全且与展板/数据库三方一致 | 三方抽样比对 |
| A-2 | 多元回归 | 因变量：分品类日清运量；自变量：经济指标（GDP/人口/旅游人次等年度插值）、农历与公历节日哑变量、台风临近指数 | 样本 ≥ 365 天；模型整体 F 检验 **p < 0.05**；节日哑变量系数显著（**p < 0.05**）且方向符合业务预期（节前为正）；**R² ≥ 0.6**；输出可解释的系数报告 | 重跑模型脚本+报告 |
| A-3 | 时间序列预测 | 至少 **2 种模型**（如 SARIMA、Holt-Winters）对日清运量做滚动回测 | 未来 7 天滚动预测 **MAPE ≤ 15%**；节日窗口（春节前后各 7 天）**MAPE ≤ 20%**；两模型误差对比表随报告交付 | 重跑回测脚本 |
| A-4 | 马尔可夫链预测 | 以"改道/路径状态转移"（如 KN_HOME→OTHER、NORMAL→EMERGENCY 暂存）或设施间流转概率构建转移矩阵 | 转移矩阵**每行之和 = 1**；基于历史估计后对留出样本做一步状态预测，**准确率 ≥ 70%**；给出稳态分布及其业务解读 | 重跑脚本+核验 |
| A-5 | 主成分分析（PCA） | 对 ≥ 8 个变量（各类别日量、节日强度、台风指数、经济指标等）做 PCA | **KMO ≥ 0.6**；前 k 个主成分**累计方差贡献率 ≥ 80%**；输出载荷矩阵并给出各主成分的业务命名；降维结果用于 A-2 回归或聚类 | 重跑脚本+报告 |
| A-6 | 外部数据接入 | 经济数据、灾害临近信息、农历-公历节日映射三类 | 三类**全部接入并参与建模**；农历转换正确性抽查近 3 年春节/中秋/端午日期**全对** | 数据字典+抽查 |
| A-7 | 运力储备建议 | 建议车辆数 = 预测日清运量 ÷ 单车日均有效运能 × 峰值系数（口径随报告公开） | 输出未来 7/30 天分品类建议，**数字随预测输入变动而联动**；春节与台风情景下建议值**高于日常值**且给出依据 | 修改输入重算 |

### 5.5 性能指标（P，DEMO 级）

| 编号 | 指标 | 验收标准 | 验证方式 |
|---|---|---|---|

### 5.6 演示场景指标（S）

| 编号 | 场景 | 走通路径 | 验收标准 |
|---|---|---|---|
| S-1 | 一车垃圾的全旅程 | 投放点建单 → 厨余车收运（专车校验）→ 中转站换大车续运（重量勾稽）→ 餐厨厂签收 → 消耗记录（outputs=沼气/柴油/有机肥） | 全程单据链完整可查，展板同步反映 |

## 六、验收判定规则与流程

### 6.1 指标分级

- **A 级（必须项，一票否决）**：D-1~D-5、D-8、F-1~F-4、F-7、V-1、A-1~A-7、S-1~S-3；
- **B 级（重要项）**：D-6~D-7、F-5~F-6、F-8、V-2~V-6、P-1~P-3；
- **C 级（加分项）**：愿景层内容（模型对比选优、情景推演 what-if、PCA 聚类分区、建议值置信区间与方案对比、性能优于标准 50% 以上等）。

### 6.2 判定标准

| 结论 | 条件 |
|---|---|
| **通过** | A 级 100% 通过 且 B 级通过率 ≥ 80% |
| **优秀** | A 级 100% 且 B 级 100% 且 C 级完成 ≥ 2 项 |
| **不通过** | 任一 A 级未通过，或 B 级通过率 < 80%（整改后重新验收） |

### 6.3 验收流程

1. **交付自验**：承建方按第五章逐项自检，提交《验收对照表》（含每条指标的验证截图/SQL 结果）；
2. **数据抽查**：验收方按 5.1 随机抽样核算勾稽与口径；
3. **现场演示**：依次演示 S-1 → S-2 → S-3 三个场景，穿插 F 类操作与 A 类模型重跑；
4. **评审结论**：按 6.2 判定并记录遗留问题清单。

## 七、范围边界（DEMO 不做什么）

| 边界项 | 说明 |
|---|---|
| 硬件对接 | 不接真实地磅、道闸、车载 GPS，重量与时间均为模拟录入 |
| 实时外部数据 | 经济/气象数据采用**离线导入**（CSV/Excel），不做实时爬取或流式接入 |
| 用户权限 | 仅做单角色演示级登录区分，不做完整 RBAC 权限体系与审批流 |
| 规模与并发 | 数据量按缩比模拟（10 万行级），不做生产级压测、备份容灾与多租户 |
| 市场化回收线深度 | 可回收物仅记录流转与消耗事实，不做交易结算功能 |
| 移动端 | 以桌面浏览器为准，不承诺移动端适配 |
